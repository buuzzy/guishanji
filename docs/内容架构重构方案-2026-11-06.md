## 零、这次分析挖到的病根（一句话）

> **内容是按"一个顺利修士的成长节奏"写的，玩家的实际节奏慢了 30–40 年，两套时间轴从来没有对齐。**

### 证据一 · 玩家实际的境界推进（24 条命实测）

| 年龄 | 境界分布 |
|---|---|
| 20 岁 | 凡身 × 24 |
| 30 岁 | 凡身 × 23、炼气 × 1 |
| 40 岁 | 凡身 × 17、炼气 × 7 |
| 50 岁 | 凡身 × 11、炼气 × 10、筑基 × 1 |
| 60 岁 | 凡身 × 7、炼气 × 10、筑基 × 2 |
| 70 岁 | 凡身 × 1、炼气 × 12、筑基 × 2 |
| 80 岁 | 凡身 × 1、炼气 × 9、筑基 × 4 |

### 证据二 · 内容写内容时假设的节奏

内容按"理想修士"分阶段：少年(16-29)=炼气、入门(30-49)=筑基、立身(50-69)=金丹、传灯(70-89)=元婴。

### 证据三 · 两者的差 = 覆盖矩阵的错位

覆盖矩阵（`阶段 × 境界段` → 实测能发出来的事件数，20 条命）：

| 阶段 \ 境界 | 凡 | 炼气 | 筑基 | 金丹 | 元婴 |
|---|---|---|---|---|---|
| 幼年 0–15 | 12 | 0 | 0 | 0 | 0 |
| 少年 16–29 | 37 | 2 | 0 | 0 | 0 |
| 入门 30–49 | **32** | 20 | **1** | 0 | 0 |
| 立身 50–69 | 15 | 30 | **6** | 0 | 0 |
| 传灯 70–89 | 2 | 18 | 23 | **0** | 0 |
| 晚年 90+ | 0 | 10 | 19 | 8 | 2 |

**读法：格子里数字低 = 那个阶段"本该有的内容"从来没在正确的境界出现过。**
- 「入门/筑基」只有 **1** 张 —— 30–49 岁是筑基的黄金年龄，却几乎没有筑基专属内容。
- 「立身/金丹」= 0、「传灯/金丹」= 0 —— 金丹修士在 50–89 岁无事可做。
- 「入门/凡」有 32 张 —— 本该给筑基修士准备的内容，全被"还在凡人的玩家"用了。

### 这一条解释了前面所有"说不上来哪里怪"

| 你的困惑 | 真相 |
|---|---|
| 72 岁去跟炉三年，很荒谬 | 内容假设 72 岁是元婴/金丹级，跟炉在内容世界里算"降格"；但玩家 72 岁才炼气 |
| 75 岁处理宗门之争，毫无用处 | 同上 —— 内容假设那时候他在传灯收徒 |
| 境界满了不突破 | 玩家实际到 50 岁才炼气，而"炼气段"的内容按 20–30 岁写的 |
| 24 岁跑商路去匠铺对照铜匣很突兀 | 内容假设 24 岁已是筑基修士能独自远行，玩家 24 岁可能还是凡人 |
| 「顾魇」凭空出现 | 内容假设玩家已经混江湖够久，能听懂幽灯堂的名号 |

⇒ **不是某张卡写坏了，是整条时间轴错位。**

## 一、分析方法：任何一块内容，问四个问题

不靠感觉，靠四张能自动生成的表。

| # | 问题 | 产出 | 能查出什么 |
|---|---|---|---|
| **问 1** | 它在人生的哪个位置？ | **覆盖矩阵**（阶段 × 境界段） | 哪些阶段是空的、哪些内容挂在错的境界上 |
| **问 2** | 它凭什么现在能出现？ | **触发条件表**（年龄/境界/概率/冷却/前提） | 75 岁还在发宗门之争（因为没有上限） |
| **问 3** | 它接着什么、留下什么？ | **因果链**（前因 → 本事件 → 后果） | 铜匣线断了童年那根钩子 |
| **问 4** | **玩家这时候真到得了这一步吗？** | **节奏对齐曲线**（玩家实际境界 vs 内容假设境界） | 本次挖到的核心病根 |

**问 4 是这次新增的维度，也是最关键的一问。**
前 3 问能看出"某张卡不合理"；问 4 能看出"整套内容的时间轴对不上"。

**分析顺序固定为：问 1 → 问 4 → 问 2 → 问 3。**
先看全局（阶段/境界错位），再看单卡（条件/承接）。
反过来就会又变成单点改。

## 二、划分：按"谁负责"切，不按"内容像什么"切

现在一个"事件"是个大包，同时背着 5 种职责，所以改任何一样都牵动全部：

```
今天的"事件" = 设定 + 触发条件 + 文案 + 后果 + 版本
```

**要拆成 5 层，各归各的文件、各归各的 Agent：**

| 层 | 是什么 | 改它要动哪里 | 现在在哪（要归位） |
|---|---|---|---|
| **L1 世界设定** | 大陆、灵根、宗门、体质、纪元、物品表、人物表 | 只改 `content/world/` | `cultivation-world.js` / `living-world.js` / `rules12-world.js` |
| **L2 剧情条目** | 事件是什么：场景 + 选项 + 后果 | 只改 `content/events/` | `content/*.js` 的 356 张卡 |
| **L3 调度** | 什么时候出这张卡 | 只改 `packages/adventure/scheduler.js` | 6 个 `monthXX()` + `cultivation.js:262-280` 的候选池 |
| **L4 文案** | 怎么说 | 只改 `content/text/` | 混在 L2 里（`readable-stories.js` 只覆盖了 66/356） |
| **L5 呈现** | 怎么显示 | 只改 `apps/preview/` + `miniprogram/` | `statLabels` 等混在引擎里 |

### 划分带来的直接好处

| 你提的问题 | 属于哪层 | 改一处即可，不会牵连别处 |
|---|---|---|
| 75 岁还在跑宗门外交 | L3 触发条件 | 改条件，不碰内容 |
| 铜匣线接不上童年 | L4 文案 + L2 的"前因声明" | 改文案与前因声明 |
| 突破卡不插队 | L3 调度 | 改调度器 |
| 轮盘寿元写死 88 | L1 设定 | 一行 |
| 雷达图混了能力和资源 | L5 呈现 | 改呈现层 |
| 90 岁没人管 | L2 内容（缺一整段） | 补内容 |

### 为什么 L3 必须合成一个

现在 6 个调度器各自问"我要出牌吗"，**谁抢到算谁**：

```js
if(month12(s,cb))return;          // 1
if(revisionMonth(s,cb))return;    // 2
if(month10(s,cb))return;          // 3
if(mundaneMonth(s,cb))return;     // 4
if(progressionMonth(s,cb))return; // 5
if(networkMonth(s,cb))return;     // 6
```

三个后果（已实测）：
- **(一) 没人有权说"这个月够了"** → 10–19 岁挤 6.1 个抉择，100 岁后 ≤0.8 个。
- **(二) 同一张卡多个调度器都能发** → 16 张卡有 2 处以上发卡位置（`reception`/`root_result`/`first_method`/`system_final` 各有 4 处）。
- **(三) 没有冷却** → 人生经历面板里同一条记录重复 170+ 次。

合成后，任何一张卡想出来，先过**四道闸**：

```
① 阶段闸：这个阶段 / 这个境界段该出这种卡吗
② 密度闸：这 10 年已经出了几个？（上限 5）这 5 年出了几个？（上限 3）
③ 冷却闸：距上次出这类卡过了多久？（同标题 60 个月内不得重复）
④ 前提闸：它自己声明的条件满足吗
```

**四道闸全在 L3。L2 的内容不需要知道自己是被谁发出来的。**

## 三、归类：给每个事件打 6 个有限标签

**标签必须是有限、可枚举的**，否则又变成新的乱。取值一旦定死，就不再增加。

| 标签 | 取值 | 用来回答 |
|---|---|---|
| `stage` 人生阶段 | 幼年 / 少年 / 入门 / 立身 / 传灯 / 晚年 | 这个阶段该有几张卡？ |
| `realm` 境界段 | 凡 / 炼气 / 筑基 / 金丹 / 元婴 | 这段内容该在哪个境界出现？ |
| `weight` 重量级 | 琐事 / 家庭 / 人生节点 / 终局 | 哪些卡值得玩家认真读？ |
| `source` 来源 | 身体 / 家人 / 师门 / 同辈 / 异乡 / 天地 | 承接是否接得上？ |
| `trigger` 触发组 | 按时间 / 按状态 / 按关系 | 这张卡凭什么现在出？ |
| `cause` 前因 | 指向另一次事件或一个 flag | 这件事是从哪来的？ |

**标签不手写** —— 现在事件本来就带着 `age>=X`、`realm>=Y`、`path==='orthodox'` 这些条件，
`scripts/content-map.mjs --json` 能直接反推出初版标签表，再人工校订。

## 四、新增内容的规矩（防止再乱）

> **规矩 1 · 新增一个事件，只许填一张表，不许去改别人已有的文件。**
>
> **规矩 2 · 如果实现一个新事件需要改 3 个以上文件，说明分层没做对，先修分层。**

事件长这样：

```js
{
  id: 'r12_child_body',
  stage: '幼年',        // 六选一
  realm: ['凡'],
  weight: '琐事',
  source: '身体',
  trigger: { kind: 'time', due: 'birth+30~66月', cond: '体质为孱弱' },
  cooldown: 0,
  cause: null,          // 开局事件可以没有前因
  scene: '...',
  choices: [
    { label: '跟先生学认药', hint: '...', cost: {}, effects: { skills: { alchemy: 2 } } },
  ],
}
```

**四类问题，各改各的字段，互不牵连：**
- 想改"什么时候出现" → 只改 `trigger`
- 想改"说什么话" → 只改 `scene` / `hint`
- 想改"产生什么" → 只改 `effects`
- 想加新内容 → 只加一条记录

#### ⚠ 顺带查出来的既有病灶（S6 要根治，本轮只登记不修）

**现象**：任何改动只要动了「哪张卡先发」，后面几十年的抽签结果就全变，
某些内容线会**整条消失**、某些会**整条冒出来**。

**根因**（逐行查出来的，不是猜）：
1. `content/cultivation-daily.js` 的 `storyOpportunity()` 用 `random(s,'events')` **一次性**抽签，
   决定「这条故事线有没有机会」；这个抽签消耗的是 **events 随机流**。
2. `packages/adventure/cultivation.js` 抽候选卡时也消耗 **events 随机流**
   （`possible[Math.floor(random(s,'events') * possible.length)]`）。
3. ⇒ 「哪张卡先发」变了 ⇒ events 流的消耗次数变了 ⇒ **后面每一次抽签的结果都变了**。
4. 而且机会窗口写的是「**第一次轮到抽签时**的年龄 + 12 年」（`storyOpportunity(s, chain.id, age(s), age(s)+12, …)`），
   窗口本身也随时序漂移。

| 长线 | S4 触发 | S5 触发 |

  （实测炼气突破卡最晚拖到 24 岁，超出 12–22 的窗口）。

#### ⚠ 全量回归抓到的一个真问题（门禁的价值所在）

`decision-browser` / `decision-static` 两道门禁红了（`'0' !== '4'`：地图上的通路条数不对）。

**根因**：S8 把地图改成「只画当前所在 + 走过的大陆」时，**顺手把「通路」也按同一个条件过滤了**
—— 两端都走过的大陆之间才画路。

**实测有多严重**：画面门禁里随机模拟出来的 **5 段人生，每一段都只在一块大陆上**
（`visited` 只有出生地）⇒ 地图上其实**一条路都没有**，
图例里「虚线 · 已知通路 / 墨绿 · 已走路线 / × 暂不通行」三条全都用不上。
⇒ 「地图只画去过的大陆」这个设计，实际上把地图的通路信息几乎全藏起来了。

**这次怎么处理的**：

- **地图本身没动**（保持 S8 批准的设计；要不要改成「连相邻大陆一起画」留给产品决定）。
- **门禁的判据换严了**：原来写死「4 条通路」，现在**从存档独立算一遍**
  （当前所在 + 走过的大陆 ⇒ 之间的通路条数），再跟地图画出来的比对。
  ⚠ 故意**不**调用规则层的 `mapView`：两边同源就等于自己跟自己比，地图画错了也看不出来。
- 顺带守住「当前所在」：地图标出的位置必须跟存档一致。
- 画面门禁也加了同口径的「通路条数」断言，并**补了一段「走过两个大陆」的人生**
