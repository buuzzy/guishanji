# 结构章程 · 归山记的内容怎么分层、怎么改

> 这份章程回答三个问题：**一件事归谁说了算**、**谁能改什么**、**改坏了谁负责拦住**。
> 归属表在 [`owners.json`](owners.json)（机器读），本文件是它背后的道理（人读）。
> 门禁是 [`scripts/check-boundaries.mjs`](../scripts/check-boundaries.mjs)，已挂进 `scripts/run-regression.mjs`。

---

## 一、六个域：依据「这件事由谁说了算」划分

内容不是按「功能」分的，是按**决定权**分的 —— 一件事的内容归谁说了算，它就归谁。

| 序 | 域 | 回答的问题 | 它管什么 | 典型文件 |
| --- | --- | --- | --- | --- |
| ⑥ | **呈现** | 玩家看到什么 | 界面、画布、地图画面、读数与控件 | `apps/preview/`、`miniprogram/` |
| ⑤ | **表达** | 这件事怎么说 | 人话翻译、称呼与词库、自动叙述文本 | `content/readable-*.js` |
| ④ | **节奏** | 时间怎么走 | 年月推进、突破门槛与阶段、寿限、期限与调度 | `packages/adventure/story-rules12.js`、`packages/adventure/life.js` |
| ③ | **因果** | 发生什么、有什么后果 | 事件表、决策细节、故事网、境界推进、结局与日常事件 | `content/cultivation-stories.js`、`packages/adventure/cultivation-v*.js` |
| ② | **角色** | 人是谁、能走多远 | 境界能力、出生条件、家人与族产、名字 | `packages/adventure/realm.js`、`birth.js`、`family.js` |
| ① | **世界** | 世界本身怎么运转 | 地图与宗门、物品与境界表、体质与地区、纪元与出生地 | `content/cultivation-world.js`、`content/rules12-world.js` |

外加两种不是内容域的角色：

| 角色 | 是谁 | 规矩 |
| --- | --- | --- |
| **⓪ 基础设施** | `packages/core/random.js`（随机流） | 序号 0 —— 所有域的共同底座，任何域都可以依赖它；它只能依赖自己。 |
| **入口** | `packages/adventure/engine.js`、`store.js`、`cultivation.js` | 把各域接起来的地方。**它是枢纽**：可以依赖任何域，任何域也可以依赖它。它只负责「接线」，不负责「内容」。 |

## 二、依赖是单向直线

```
⑥呈现 → ⑤表达 → ④节奏 → ③因果 → ②角色 → ①世界 → ⓪基础设施
```

**序号大的可以依赖序号小的，反过来不行。**

为什么是这条直线？因为它就是「决定权」的传递方向：
玩家看到的东西建立在「怎么说话」上，「怎么说话」建立在「事情怎么发生」上，
「事情怎么发生」建立在「人能做什么」上，「人能做什么」建立在「世界是什么样」上。
**越层向上依赖 = 下层被上层牵着走 = 改下层要顾上层 = 没人敢改。**

还有一条**层方向**，跟域无关：

```
packages/adventure/（规则层） → content/（数据层）      ✔ 规则读数据，天经地义
content/（数据层）             → packages/adventure/    ✘ 不许
```

数据层回头找规则层，两边就互相踩脚：改规则要顾内容，改内容要顾规则。
实测有 **7 条**这样的反向依赖（见下面第三节）。

## 三、许可证：已经越界的，怎么留住

**许可证（permit）= 一条「这里允许越界」的登记**，写在归属表的 `permits` 里，四样东西缺一不可：

1. `from` / `to` —— 具体哪一对文件（或哪一侧通配）；
2. `reason` —— **为什么允许**（不许写「历史原因」这种废话）；
3. `since` —— 哪一阶段登记的；
4. `status` —— 「待拆」还是「S9 撤」—— 写清楚它将来怎么消失。

规矩：

- **没登记的越界 ⇒ 门禁报红。** 新的越界必须先申请许可证。
- **登记了但用不上的 ⇒ 门禁报红。** 许可证不许发霉（改完代码忘了撤登记，门禁会骂你）。
- **同一对依赖登记两次 ⇒ 门禁报红。**
- **没写理由 ⇒ 门禁报红。**

现在有 **11 条**许可证，来源分两类：

| 类型 | 条数 | 是什么 | 怎么消失 |
| --- | --- | --- | --- |
| 层方向（数据→规则） | 7 | 内容表要执行器提供的判定函数（`mundaneRequirements`、`canCultivate`…） | 把这些纯判定下沉到因果域 |
| 域方向 | 4 | `content/adventure.js` 汇总三个域的道具表（3 条）；`life.js` 要用自动事件的文字（1 条） | S9 拆 `adventure.js` 时一并解决 |

## 四、门禁到底在拦什么

`node scripts/check-boundaries.mjs` 核对四件事，**任何一件不通过 ⇒ 退出码 1**：

> 「源文件」= `content/`、`packages/`、`apps/`、`miniprogram/` 下的 `.js` 文件
> （不含生成物 `miniprogram/subpkg/xianxia/runtime/`、测试文件、`scripts/` 里的工具）。
> 工具与测试不归内容域管 —— 它们是**看内容的人**，不是内容本身。

| # | 规则 | 拦的是 |
| --- | --- | --- |
| ① | **每个源文件都要有归属** | 新加文件忘了登记 —— 归属表漏登记 = 没人负责改它 |
| ② | **域方向不越界** | 上层依赖了不该依赖的下层 |
| ③ | **层方向不越界** | 数据层反向依赖规则层 |
| ④ | **许可证不许发霉 / 不许重复 / 不许没理由** | 登记与现实脱节 |

**这套门禁不检查代码写得对不对**，只检查**结构**。内容对不对由内容保真门禁管
（`scripts/verify-events-fidelity.mjs`、`scripts/verify-event-sequence.mjs`）。

## 五、改东西的时候怎么办

| 你要改的 | 找谁 | 要不要许可证 |
| --- | --- | --- |
| 一条事件的正文、选项、后果 | ③因果 → `content/cultivation-stories.js` | 不要（层内改动） |
| 境界突破的门槛、寿限、阶段 | ④节奏 → `packages/adventure/story-rules12.js` | 不要 |
| 某个人物的身世、家人 | ②角色 → `packages/adventure/birth.js` / `family.js` | 不要 |
| 一段话怎么说 | ⑤表达 → `content/readable-*.js` | 不要 |
| 界面上的读数、地图画法 | ⑥呈现 → `apps/preview/` / `miniprogram/` | 不要 |
| **要跨着改两个域** | 先看边界门禁 | **要** —— 先在归属表里申请许可证 |

改完跑一遍：

```sh
node scripts/check-boundaries.mjs              # 结构
node scripts/run-regression.mjs --group=fast   # 全部快门禁（含结构）
```

## 六、这套章程管不到的事

- **不判断内容好不好。** 「这句话好不好听」「这个选择有没有意思」不在章程范围内。
- **不许为了让门禁变绿而削弱断言。** 越界要解决就解决（改代码去越界），
  或者登记许可证并写清怎么消失 —— **不许改门禁本身**。
- **许可证不是万能钥匙。** 一条越界登记超过一个阶段还没拆，就要在下一轮的复盘里点名。
