> 这是一份**总纲**：把「归山记」这套修仙人生模拟的剧情设计，从世界观到门禁，完整讲一遍。
>
> **怎么读**
> - 只想知道「这游戏长什么样」→ 读第 1、2、4 章。
> - 要改内容（写卡、加线、改数值）→ 读第 4、6、9、14 章。

> **数据来源**：所有数字都是 2026-11-08 从**源码与门禁实跑**取出来的，不是抄文档。
> 凡文档与源码不一致的，本文在**第 13 章**逐条列出来，并在正文就地标注。
>
> **一句话概括**：归山记不是「修仙模拟器」，是**「一生只能过一遍」的人生模拟器**——
> 修仙只是其中一条路，剩下的人生同样要交代。所有设计决策都是围绕这一句展开的。

## 第 1 章：设计目标与产品定位

### 1.1 这是什么产品

**归山记**是一款微信小程序端的修仙人生模拟游戏。玩家给一个「机缘种子」，游戏替他/她生成一生：
从出生、童年、入门（或与修仙无缘）、修行、冲关、远行、返乡、晚年，一直到死。

- **产品形态**：只有微信小程序端（网页端 2026-11-08 已清理，见 `docs/browser-gate-coverage.md`）。
- **规则版本**：只保留**规则十二**。规则 5–11 的执行器、事件表快照、内容副本已全部删除，旧档一律拒收。
- **内容规模**（实跑）：

### 1.2 三条设计原则

这三条贯穿全仓库，任何一次改动都要拿它们当判据。

#### 原则一：一生只有一次，**没有重来**

玩家不能读档刷一个「更好的结局」——每一个选择的后果都写进状态，一辈子带着走。
所以整套设计围着**不可逆**：

- 突破失败留**旧伤**（`body.damage`，永久但很轻），不扣体力（体力是资源，扣了会「越输越没戏」）。
- 长线里的「自私」选项会让同伴记住你；旁人的态度由你的选择累积，不是一次判定。
- 死亡是**结局**，不是失败状态：`breakthrough_lost`（陨落于冲关）、`battle_lost`（道途止于此处）各有正文。
- 存档里**不存**「如果重来会怎样」。

#### 原则二：**玩家能懂**才算内容

「看懂」有三个层面，缺一不可：

1. **看得懂眼前**：选项提示语只写玩家**已经知道的**条件、费用和危险；不展示后台概率，不讲存档、系统、旧规则。
2. **想得出为什么**：每张卡的正文只讲**场景**，规则条款归到提示语里；「一句一件事」。
3. **信得过后果**：后续卡读**真实发生过的选择**（家人是否在世、同伴是否还活着、商路是否通），不读抽象标记。

⇒ 这一条逼出了「**表达域**」这套东西（第 7 章）：规则层管事实，表达域管说法，两边分开。

#### 原则三：**没走上修仙路，也确实活过一段可被记住的人生**

这是凡人线存在的全部理由，也是「与修仙无缘」这一整类背景存在的理由。

- 凡人线是**五张直线**（起 / 承 / 转 / 合 / 结），不是十几张卡的堆砌。
- 凡人线的结局是**独立结局**（`mortal_home` 故乡岁月、`mundane_craft` 一门手艺一世风霜、`mundane_family` 人间仍有灯火），不写成「修仙失败版」。
- 无灵根不等于无故事：凡人能学辨药、剑术、谋生手艺，能回乡、能探亲、能替修士跑腿。

### 1.3 不做什么（明确的负向约束）

| 不做 | 为什么 |
| --- | --- |
| 不复刻任何一部小说的设定 | 灵根分布、境界门槛、寿元、收入、相遇与风险**都是本作的设计参数**，不是史实也不是小说设定 |
| 不用真实历史年份与统治者 | 世界是架空的 |
| 不做网页端 | 2026-11-08 已清理，只做小程序 |
| 不留旧规则版本 | 规则 5–11 已删，旧档拒收 |
| 不在生成物里改剧情 | 生成物（`miniprogram/subpkg/xianxia/runtime/engine.js`）会被下次构建覆盖 |

## 第 2 章：世界层（世界本身怎么运转）

> 归属：**①世界域**。文件在 `content/cultivation-world.js`、`content/living-world.js`、`content/rules12-world.js`、`content/realms.js`、`content/items.js`、`content/ends.js`、`content/adventure.js`。

### 2.1 四片大陆

世界是四块被界海隔开的大陆，环成一个不规则的环：

```
        临潮大陆(tide)
       ╱            ╲
青岚大陆(home)    浮屿界(sky)
       ╲            ╱
        烬原大陆(ember)
```

| id | 名称 | 专长 | 关键地点 |
| --- | --- | --- | --- |
| `home` | 青岚大陆 | 药草、剑术与宗门授业 | 竹溪村、清河城、渡云宗、回风谷 |
| `tide` | 临潮大陆 | 坊市、航路与海岛遗迹 | 小潮湾、听潮港、听潮门、碧礁岛 |
| `ember` | 烬原大陆 | 地火、矿石与炼器 | 赤沙井、流沙驿、赤炉宗、地火矿 |
| `sky` | 浮屿界 | 阵法、界门与域外探索 | 明霞屿、悬桥市、悬灯院、裂隙域外 |

- **商路是通的，但要钱、要境界、要时间**：跨界要花路费（按路线段数算）、耗月份，浮屿界的普通跨界阵还要求筑基修为。
- **路会被掐断**：关卡封航、宗门对峙都会让某条路临时不通（`c.closed` 记录），这时「回家」「寄东西」这些选项会被**明确禁用并给出原因**。
- 跨大陆不是一个传送点，是一段**有月数、有花费、有风险**的旅程。

### 2.2 五条路（`PATHS`）

| id | 名称 | 住处 | 引路人 | 说明 |
| --- | --- | --- | --- | --- |
| `orthodox` | 宗门修士 | 外门弟子院 | 闻竹 | 受门规约束，以任务与考核取得资源 |
| `loose` | 散修 | 坊市租屋 | 游方药师 | 自行买书、做工、结伴，材料自己筹 |
| `demonic` | 魔修 | 幽灯堂弟子院 | 幽灯堂主 | 修习禁术，堂中以实力分配资源，离开可能被追索 |
| `beast` | 妖修 | 山林石穴 | 山中老猿 | 以妖身修行，守住栖地 |
| `mortal` | 凡俗生活 | 故乡旧屋 | 村中先生 | 做工、读书、照顾亲人，仍可能遇到机缘 |

⚠ **「路」与「童年」是两件事**（`path` vs `upbringing`，`content/background-stories.js:48-53`）：

- `path` = 这条身世把你**送进哪条路**；
- `upbringing` = 你**童年过的是什么日子**（ordinary 有人照看 / loose 跟商路走 / demonic 魔道收养 / beast 妖身）。

⇒ 「家道中落」（名门大户当散修）这条路走 `loose`，但童年仍是 `ordinary`
⇒ **名门大户不会因为当散修就去跟商队跑货**。

### 2.3 六种灵根（`ROOTS`）

| 灵根 | 等级 `grade` | 修行速率 `rate` | 说明 |
| --- | --- | --- | --- |
| 松骨灵根 | 3 | ×1.25 | 单灵根，吸纳灵气较快，容易得到长老培养 |
| 水木灵根 | 2 | ×1.05 | 双灵根，适合药田与丹术 |
| 金火灵根 | 2 | ×1.05 | 双灵根，适合御剑与炉火 |
| 三相灵根 | 1 | ×0.80 | 杂灵根，入门较慢，常从外门任务起步 |
| 五行杂灵根 | 0 | ×0.55 | 五行混杂，宗门可能只收为杂役 |
| 未显灵根 | −1 | ×0.40 | 常规测灵石未能发现，需另寻功法或走凡俗道路 |

**灵根的三条硬规矩**：

1. **灵根不由背景决定**。背景只讲清「你从什么处境来」，路的归属由灵根决定（`content/background-stories.js:30-33`）。不许用「身世」偷偷改灵根。
2. **灵根不能被创造**。`root_review` 的复测只可能把「未显」变成「五行杂灵根」，或确认「无灵根」；`choose10` 末尾有一条显式兜底：任何路径标签、血、月份乘数都**不能造出灵根**（`packages/adventure/story-shared.js:177-182`）。
3. **灵根能被发现、也能被误判**。背景故事线（`background_root_hurt` 旧伤压住根骨）与童年高热复诊，都是「本来有但被挡了」的写法。

**「未显灵根」与「确认无灵根」是两件事**：
`rootStatus` 三态 `unverified`（未测）→ `present` / `absent`（测过了）。
`absent` 的人仍可学**凡俗技艺**（辨药、剑术、谋生），只是不能运气周天。

### 2.4 五层境界与寿元

| 序号 | 境界 | 基础寿元 | 突破门槛 `REQUIRED_PROGRESS` | 完整心法月数 | 要备主药 |
| --- | --- | --- | --- | --- | --- |
| 0 | 凡身 | 88 | — | — | — |
| 1 | 炼气 | 120 | 18 | 不限 | 否 |
| 2 | 筑基 | 210 | 120 | 不限 | 否 |
| 3 | 金丹 | 350 | 220 | 120 | 是 |
| 4 | 元婴 | 560 | 320 | 240 | 是 |

⚠ **寿元不是境界表里那个数字**。实际能活到几岁由 `lifespan12(s)` 算：

```
境界 0（凡身）  → 自然寿限（体质决定的 45–84 岁区间）
境界 1（炼气）  → 自然寿限 + 45
境界 ≥ 2（筑基+）→ 境界基础寿元 + (自然寿限 − 66) − 旧伤损失
```

算完写进 `state.life.cultivation.lifespanLimit`，**呈现层只读这个值**，不许自己算、不许读境界表
（`packages/adventure/engine.js:131-157`）。这条曾经出过 bug：小程序读境界基础寿元、登记卡上写的是实际寿元，两边对不上。

## 第 3 章：角色层（人是谁）

> 归属：**②角色域**。文件在 `packages/adventure/birth.js`、`family.js`、`realm.js`，`content/living-world.js`、`content/novel-names.js`。

### 3.1 出生：种子决定的事实

`birthConfiguration(seed, overrides)` 用**独立的 `birth` 随机流**（`createStreams(seed)`）依次抽：

```
时代 → 大陆 → 家族 → 住址 → 姓名 → 性别 → 灵根 → 志向
```

⚠ **出生用的是一个独立的随机流**，不与人生推进共用 ⇒ 改后续内容不会改掉「你是谁」。

### 3.2 体质：四型，一型才体检

`initialize12` 抽 `body.type`：

| 类型 | 概率 | 自然寿限跨度 | 修行速率 | 体力 |
| --- | --- | --- | --- | --- |
| `frail` 先天孱弱 | 15% | 短 | 慢 | 低 |
| `sturdy` 常人 | 21% | 中 | 中 | 中 |
| `mighty` 天生神力 | 2% | 中上 | 中 | 高 |
| `ordinary` 寻常 | 62% | 中 | 中 | 中 |

**「身体检查」卡只给 `frail`**（2026-11-07 · T3 改）：

- 以前人人都有（实测 87%），而且排在 2–5 岁、比任何童年事件都早 ⇒ 每个孩子 16 岁前固定多一张卡。
- 现在只有先天孱弱的孩子才查，且**排在 6–9 岁**、**占掉**那一段的位置 ⇒ 一生 16 岁前只有**三张**童年卡。
- ⚠ 魔道 / 妖兽出身不加进来：他们没人照顾不等于身体该查；而且 6–9 岁那段本来就有专属卡（照看者 / 夜里的呼救），体检会占掉他们的位置。

### 3.3 名字：全套随机，但角色对得上

- **随机改名池** 81 个名字（男 46 / 女 35），每人带 `book`/`author`/`source`。
- 规则层用**别名**（`许执事`、`闻竹`、`嵇萝`…），文案层用**随机真名**。替换发生在 `prose()`（`packages/adventure/progression.js:43-47`）。
- ⚠ 别名 → 真名的映射必须**双向可查**：`introduceText()` 靠它给首次出现的人物加身份注解「（幽灯堂药师）」。
- 宗门名也是随机的：`栖云/照水/青衡/松岚/归鹤/玄溪/临月/回霜` + `门`/`宗`，按宗门规模选后缀。

### 3.4 家人：两个人，各有各的死期

`familyState()` 生成两位家人：

| id | 身份 | 死期 |
| --- | --- | --- |
| `parent` | 家中长辈（按家族不同换说法） | 约 55 岁（初始化时按家族改写） |
| `cousin` | 家中亲人（照管旧屋与日常往来） | 约 85 岁 |

- 家人**按真实位置变老**，不在你眼前的人也会死 ⇒ **讣告要走商路**（同大陆 3 个月、异大陆 18 个月才送到）。
- 家人死了**不能复活**（`applyEffects` 里「不能让已死人物复活」是硬报错）。
- 35 岁添堂亲的孩子，70 岁添下一代 ⇒ 晚年的「下一代」是规则生成的，不是文案吹的。

### 3.5 五轴能力（雷达图）

小程序端的五边形雷达，角序固定：**悟性 / 胆识 / 仁心 / 心境 / 体魄**。

⚠ 2026-11-07 · T4 换过一次轴：**体力（资源）出雷达、体魄（能力）进雷达**。
体力会被耗掉又回来，画进雷达图会忽高忽低；体魄只增不减，才是「能力」。

## 第 4 章：人生层（一生怎么过）

> 归属：跨**②角色 / ③因果 / ④节奏**三域。文件在 `content/background-stories.js`、`content/story-network.js`、`content/cultivation-stories.js`、`content/cultivation-joints.js`、`content/mundane-kept.js`、`packages/adventure/story-rules12.js`、`mundane-life.js`。

### 4.1 童年：三个窗口，各有各的由头

`content/story-network.js::CHILD_WINDOWS`：

| 窗口 | 候选事件 | 设计意图 |
| --- | --- | --- |
| 6–9 岁 | `child_school` `child_apothecary` `child_clan` `child_noble_school` `child_keeper` `child_friend` `child_caravan` `child_secret` | 童年最早的第一件「你还没法自己决定」的事 |
| 10–12 岁 | `child_relic`（旧屋梁上的铜匣） | 童年那条线索的尾巴 |
| 13–15 岁 | `child_recruit` `child_teacher` `child_family_vow` `child_noble_recommend` | **13–15 岁那段要有由头**：读过书、学过药、家是世家，才有人上门来找你 |

- 童年卡**一条都不许发霉**（`scripts/verify-life-richness.mjs` 断言）。
- 童年**组合不许流水化**：实测 19 种不同组合（下限 8）。
- 童年卡的措辞会**按出身分三套**（山村 / 名门 / 世家）—— 名门大户的旧物是「家传的」，不是「梁上落下来的破铜匣」。

### 4.2 背景故事线：15 条，**必答卡不是岔路**

这是整套设计的入口级机制。玩家在轮盘上看到的出身与灵根，**在这里落地成一条身世**。

**一条背景 = 一张必答卡，两个选项，只指向一条路。**

| 侧 | 条数 | 规则 |
| --- | --- | --- |
| 入宗门侧 | **11** 条 | 直接走到**测灵根**那张唯一的决策卡 |
| 与修仙无缘侧 | **4** 条 | 直接走进凡人的日子（`path:'mortal'`），之后由凡人线接手 |

11 条入宗门侧分四种去向：

| 去向 | 背景卡 | 走向 |
| --- | --- | --- |
| 山门 | `background_ill_parent` 父亲的咳疾、`background_saved_stranger` 你救过的那个人、`background_born_sect` 生在宗门人家、`background_noble_house` 名门望族、`background_noble_recommend` 郡里的名帖、`background_cultivator_family` 修仙世家的旁支、`background_clan_legacy` 家传护符与旧盟 | `reception`（山门外的队伍）→ 测灵根 |
| 坊市散修 | `background_noble_exile` 家道中落、`background_healer_note` 游方药师留下的笔记 | `path:'loose'` |
| 幽灯堂 | `background_dark_sect` 收养你的幽灯堂 | `path:'demonic'` |
| 妖身 | `background_beast_born` 老猿教你控制妖身 | `path:'beast'` |

4 条无缘侧（三个出身都有）：`background_weak_body` 生下来就弱、`background_root_hurt` 旧伤压住了根骨、`background_family_debt` 家里欠着债、`background_orphan_war` 战乱里失了父母。

**四条硬规矩**：

1. **出身先过滤，再按灵根过滤**。以前这张表按灵根分池抽、出身不参与 ⇒ 轮盘写着「名门大户」却抽到「战乱里被游方药师救过」（实测：名门大户只有 10% 抽到配得上的身世卡，山村药农 **0%**）。现在每条背景写明 `origins` ⇒ 匹配率 100%。
2. **模数按「这条命能走的路」取**：没有可修炼根骨的命，只从无缘那 4 条里选；能修炼的，只从入宗门那 11 条里选。
3. **绝不改灵根**。路的归属由灵根决定，背景只负责讲清来处。
4. **两个选项通向同一条路**：它们表达的是**两种态度**（急 / 稳），不是两条岔路 ⇒ 玩家在这张卡上**做不了「改变命运」的决定**，真正能改变命运的是后面的测灵根。

⚠ **排队那一段是铺垫，不是卡**：12 个月的等待本身就是排队，留在旁白里 ⇒ 开局卡数不增加，密度闸不会被开场塞满。

### 4.3 入门必答串：五环

**测灵根 → 宗门部门 → 心法选定 → 重心（首次授业）→ 炼气突破**

- **测灵根是全程唯一的决策点**；其余几环都是**必答**（两个选项通向同一条路）。
- **部门由规则层算**（`department12`），入门时定下、终身不改：

| 灵根 | 部门 | 依据 |
| --- | --- | --- |
| 松骨灵根 | 执事房 | 单灵根最容易被长老看在眼里 |
| 水木灵根 | 药田 | 这灵根适合药田与丹术 |
| 金火灵根 | 丹房 | 适合御剑与炉火 |
| 三相灵根 | 器堂 | 入门慢，先从外门器物做起 |
| 五行杂灵根 / 杂役 | 药田 | 宗门多半只收作杂役 |

- ⚠ **部门只影响后续卡的可选项，不改数值**。
- **心法由规矩定，不由玩家挑**：`methodId12` 算出宗门路给宗门基础卷、幽灯堂给守魂诀、妖身给淬身法、散修按灵根好坏给清息诀或磐石吐纳。
- **心法在测灵根之后、重心之前定下** ⇒ 冲关卡一定排在心法之后（否则冲关卡上只剩「点不动」和「白等」两条路，是废卡）。

**长线的四条机制**：

1. **不跟别的卡抢**。条件齐了当月就发，不排进随机候选池（以前排进候选池 ⇒ 窗口只有 12 年时，很多人生里一条长线都发不出来，实测 `sect_repair` 40 条人生只触发 2 条）。
2. **判断不含随机数** ⇒ 给定同一条人生，该发哪条长线、什么时候发，**每次都一样**。
3. **`ageEnd` 按境界段推导，不手填**：`ageEnd = max(下一境窗口上界 − 30, 本线起始年龄 + 12)`（`content/cadence-table.js:117-121`）。手填一个「看起来更合适」的值，门禁立刻报红。
4. **给突破卡让路**：玩家已在某个境界的窗口里、进度也攒够了 ⇒ 先让他突破，别用长线把他卡住（`packages/adventure/scheduler.js:182-186`）。

⚠ **`ROAD_CHAINS` 字面上只有 12 条**，另外 4 条（`sect_feud` / `loose_escort` / `dark_sacrifice` / `beast_eclipse`）是**装配期追加**的。
「长线 id 清单」住在 `content/chain-ids.js`（叶子文件，不 import 任何东西 ⇒ 永远不在环里），内容层加载时**自己核对**两份清单，对不上当场抛错。

### 4.5 接头卡：一条线走完之后的那张桥

16 条线 × 3 种收尾 = **48 张接头卡**，id 固定为 `<线id>_joint_settled` / `_joint_pending` / `_joint_hidden`。

| 收尾 | 选项 id | 含义 |
| --- | --- | --- |
| `open` 接下这件事 | `open` | 把这条线接进下一段 |
| `hold` 先按住 | `hold` | 留住退路 |
| `take` 走自己的路 | `take` | 关掉这条路 |

**「下一拍」由上一条线怎么收尾决定**（`nextBeat12(chainId, ending)`）：

| 上一条线收尾 | 下一拍可达集合 |
| --- | --- |
| `open` | 最远的一档 + 中间的一档都开 |
| `hold` | 只开中间那档，最远那档关闭（给出关闭原因） |
| `take` | 两档全关 |

**每条线各接一张「下一拍」卡**（`NEXT_BEAT`，16 条）：

| 线 | 下一拍卡 | 开放档 | 线 | 下一拍卡 | 开放档 |
| --- | --- | --- | --- | --- | --- |
| `sect_repair` | `r12_patron` | prepare | `dark_ledger` | `r12_direction_0` | travel |
| `sect_feud` | `r12_direction_0` | travel | `dark_sacrifice` | `r12_foundation_supply` | serve |
| `sect_trial` | `r12_foundation_supply` | serve | `beast_home` | `echo_teacher` | follow |
| `loose_contract` | `thin_root_offer` | mine | `sect_return` | `sect_rebuild` | lead |
| `loose_escort` | `family_gate` | stones | `loose_portal` | `echo_friend_visit` | help |
| `loose_relic` | `family_support` | stones | `dark_method` | `manual_study` | blood |
| `dark_pursuit` | `custody_terms` | accept | `beast_form` | `family_dispute` | stop |
| `beast_war` | `world_raid` | defend | `beast_eclipse` | `r12_direction_0` | retreat |

⚠ `r12_direction_0` 被三条线共用（`sect_feud` / `dark_ledger` / `beast_eclipse`），但各自挑**不同档位**（travel / work / retreat）——这是刻意的。
⚠ **关门写在 `requires.flagsAbsent`**，不是 `choice.available`（后者会被 `progressionChoice` 整个覆盖 ⇒ 联动静默失效）。

⚠ **接头卡只写旗标，不扣数值**：旗标由下一拍那张卡的选项读，读到的效果是「这个选项对你开放/关着，理由是什么」。
⚠ **旗标名是驼峰**（`<线id><Open|Hold|Take>`，**不许下划线**）——`validateRun` 要求旗标名匹配 `/^[a-zA-Z][a-zA-Z0-9]{0,50}$/`，带下划线 ⇒ 每次存档被判无效。

⚠ **接头卡必须排在长线档之前**：接头卡排在队列里，而队列里的卡要等 `activeChain` 为空才发得出去 ⇒ 线一开就占住 ⇒ 接头卡要等这一条新线走完才轮得到（实测中位延迟 9 个月，最长 6 年 ⇒ 桥早就没有意义了）。

> 来源：`docs/结构章程.md` + `docs/owners.json`（机器读）。门禁：`scripts/check-boundaries.mjs`。

### 5.1 六个域：按「这件事由谁说了算」划分

内容不是按「功能」分的，是按**决定权**分的。

| 序 | 域 | 回答的问题 | 它管什么 | 典型文件 |
| --- | --- | --- | --- | --- |
| ⑥ | **呈现** | 玩家看到什么 | 界面、画布、地图画面、读数与控件 | `miniprogram/` |
| ⑤ | **表达** | 这件事怎么说 | 人话翻译、称呼与词库、自动叙述文本 | `content/expressions/` |
| ④ | **节奏** | 时间怎么走 | 年月推进、突破门槛与阶段、寿限、期限与调度 | `packages/adventure/story-rules12.js` `cadence.js` `scheduler.js` |
| ③ | **因果** | 发生什么、有什么后果 | 事件表、决策细节、故事网、境界推进、结局与日常事件 | `content/cultivation-stories.js` `packages/adventure/cultivation.js` |
| ② | **角色** | 人是谁、能走多远 | 境界能力、出生条件、家人与族产、名字 | `packages/adventure/birth.js` `family.js` `realm.js` |
| ① | **世界** | 世界本身怎么运转 | 地图与宗门、物品与境界表、体质与地区、纪元与出生地 | `content/cultivation-world.js` `rules12-world.js` `realms.js` |

外加两个不是内容域的角色：

| 角色 | 是谁 | 规矩 |
| --- | --- | --- |
| **⓪ 基础设施** | `packages/core/random.js`（随机流） | 所有域的共同底座，任何域都可以依赖它；它只能依赖自己 |
| **入口** | `packages/adventure/engine.js`、`store.js`、`cultivation.js` | 把各域接起来的地方。它只负责「接线」，不负责「内容」 |

### 5.2 依赖是单向直线

```
⑥呈现 → ⑤表达 → ④节奏 → ③因果 → ②角色 → ①世界 → ⓪基础设施
```

**序号大的可以依赖序号小的，反过来不行。**

为什么：这条直线就是「决定权」的传递方向——玩家看到的东西建立在「怎么说话」上，「怎么说话」建立在「事情怎么发生」上，「事情怎么发生」建立在「人能做什么」上，「人能做什么」建立在「世界是什么样」上。
**越层向上依赖 = 下层被上层牵着走 = 改下层要顾上层 = 没人敢改。**

还有一条**层方向**（跟域无关）：

```
packages/adventure/（规则层） → content/（数据层）      ✔ 规则读数据，天天如此
content/（数据层）             → packages/adventure/    ✘ 不许
```

⚠ 现在有 **11 条**许可证（7 条层方向 + 4 条域方向）。**新的越界不许再登记** ⇒ 只能改结构，不能加豁免。

### 5.3 门禁在结构层拦什么

`node scripts/check-boundaries.mjs` 核对四件事，任何一件不通过 ⇒ 退出码 1：

| # | 规则 | 拦的是 |
| --- | --- | --- |
| ① | 每个源文件都要有归属 | 新加文件忘了登记 |
| ② | 域方向不越界 | 上层依赖了不该依赖的下层 |
| ③ | 层方向不越界 | 数据层反向依赖规则层 |
| ④ | 许可证不许发霉 / 不许重复 / 不许没理由 | 登记与现实脱节 |

⚠ **这套门禁不检查代码写得对不对**，只检查**结构**。
⚠ **不许为了让门禁变绿而削弱断言。**

### 5.4 装配顺序就是内容的顺序

`content/cultivation-stories.js` 末尾的装配链：

```
决策细节 → 门派忠诚 → 生涯修订 → 人脉网络 → 长线推进 → 修订九
→ 共用内容 → 俗世生活 → 规则十二 → 接头卡 → 背景故事
```

⚠ **顺序不能改**：后装的安装器会**改写**先装的节点。

## 第 6 章：节奏层（什么时候发卡）

> 归属：**④节奏域**。文件在 `packages/adventure/gates.js`（四道闸）、`scheduler.js`（调度顺序）、`cadence.js`（突破判断）、`content/cadence-table.js`（数据）。

### 6.1 四道闸（只有一份实现）

以前密度、冷却、阶段这三件事**谁都不管**：

- **密度**：一局人生里最挤的十年有 14 张抉择卡（实测 40 条命）——玩家在十六岁那年被 6 张卡同时追着打。
- **冷却**：同一条旁白在 60 个月里重复 20 次——同一句话反复说，像卡带了。
- **阶段**：没有「这张卡属于哪一段人生」的概念 ⇒ 童年卡能在四十岁发出来。

⇒ 现在三道闸**只有这一份实现**（`packages/adventure/gates.js`），规则层用它、审计用它、门禁也用它。

| 闸 | 判据 | 实现 |
| --- | --- | --- |
| **密度闸** | 日常卡每 10 年 ≤ 5 张、每 5 年 ≤ 3 张 | `densityAllows` |
| **冷却闸** | 同一张卡 / 同一句旁白，60 个月内不许再来 | `cooldownAllows` / `titleAllows` |
| **阶段闸** | 卡自己声明「属于哪一段人生 / 哪个境界段」 | `stageAllows` + `content/card-stages.js` |
| **前提闸** | 选项的 `requires` 不满足 ⇒ 选项禁用并给出原因 | `unmet()` |

**豁免名单**（`classifyCard`）分两类，**每一条都写清理由**（不许靠前缀形状猜）：

| 类别 | 内容 | 豁免？ |
| --- | --- | --- |
| `structural` **结构性** | 突破卡与前置、入门那六步、宗门考核、长线、终章与急讯、凡人一生、背景故事 | ✅ 豁免 |
| `daily` **日常** | 玩家的日常决定 + **承接上一张卡的后果**（回家链、集市后续、经历回响、人脉网络、俗世生活线、看管与入路） | ✅ 豁免（但算进「日常口径」指标） |

⚠ **豁免的不是「不重要」，而是「不能拦」**：

- 拦住突破卡 ⇒ 玩家永远攒不够条件，这一境就废了；
- 拦住后续卡 ⇒ 上一张卡的后果不能不落地，让人白等；
- 拦住长线中间一段 ⇒ 整条线断掉。

⚠ **闸的豁免范围一个字没变**：两类加起来还是原来那份并集（由 `tests/fixtures/gate-exemptions.json` + `tests/gates.test.mjs` 逐条锁死）。

### 6.2 调度顺序：每个月「谁先说话」

`packages/adventure/scheduler.js::scheduleMonth` —— **顺序是行为的一部分，不是风格问题**：

| # | 档 | 管什么 | 为什么在这个位置 |
| --- | --- | --- | --- |
| 1 | 境界十二 `month12` | 突破与寿限 | 每个月最硬的那件事，先问它 |
| 2 | 里程碑 `milestoneMonth` | 突破卡 | 人生节点，不跟别的卡抢 |
| 3 | 接头 `jointCardMonth` | 线走完的回响 | 必须在新线开起来之前发出去，否则桥会烂掉 |
| 4 | 长线 `longChainMonth` | 人生某一段该开始的那件事 | 也不跟别的卡抢 |
| 5 | 修订九 `revisionMonth` | 生涯修订 | 只在没有俗世支线时插话 |
| 6 | 规则十 `month10` | 能不能修炼、能不能考核 | |
| 7 | 俗世生活 `mundaneMonth` | 凡人线 | |
| 8 | 长线推进 `progressionMonth` | 备主药、多年修行、渡劫准备 | |
| 9 | 人脉网络 `networkMonth` | 授业与功法机会 | |

⚠ 任何一次调换都会改变玩家看到的事件顺序 ⇒ 属于**有意行为变更**，必须走「变更前基线 → 差异审查 → 变更后基线」流程。

**「已排好的事」不过闸**：`arriveRaw` 走的是队列里的家信、战事、长线步骤、长线第一张、接头卡 ⇒ 拦它＝让人家白等。

### 6.3 突破卡：唯一的判断

`packages/adventure/cadence.js::breakthroughDue` —— **这个月该不该发突破卡**，只有这一份。

发卡条件（全部满足才发）：

1. 境界 < 4，路径不是 `mortal`，**有灵根**，已入门（`admissionDone`），当前没有待回应卡 / 行动在进行。
2. **心法已定**（炼气这一级）：`network_method` 卡已出过 ⇒ 否则冲关卡上只剩「点不动」与「白等」两条路 = 废卡。
3. **材料与完整法门**（只对金丹 / 元婴）：主药槽逐项齐、完整心法练够 `METHOD_MONTHS` ⇒ 不发卡，胜过发一张废卡。
4. **进度够**（`REQUIRED_PROGRESS`）⇒ 立刻发，不看岁数。
5. **四次机会没用完**，且过了冷却期（`retryAt`）。
6. **「再准备一段时间」（wait）不算「这张卡已经答过」** ⇒ 选 wait 不消耗机会（机会只有四次，不能被「再等等」花光），冷却期过后同一张卡重新发出来。

**窗口上界时突破卡可以插队**（`urgent`）：寿元不等人 ⇒ 哪怕这次大概率失败，也比「错过整个窗口、一辈子卡在炼气」强。
⚠ 只放宽 `activeChain` 这一条；队列里排好的事（家信、战事、长线步骤）仍然挡着。

**突破失败只留旧伤**（`body.damage`，永久但很轻），**不扣体力**、成功也**不回体力**：

- 以前失败一次扣 8–28 点体力 ⇒ 掉到 40 以下就吃判定上的减分 ⇒ **越输越没戏**（实测：连输三次的修士后面几次冲关全败）。
- 体力是资源，只由调养与丹药回；成功回的是**体魄**（练出来的本事不会掉）。

### 6.4 冲关参数（`BREAKTHROUGH`）

| 境 | 底分 `base` | 技艺权重 | 悟性权重 | 失败留旧伤 | 做工换料月数 |
| --- | --- | --- | --- | --- | --- |
| 炼气 | 70 | ×0.20 | ×0.12 | 1 | 36 |
| 筑基 | 62 | ×0.20 | ×0.12 | 1 | 36 |
| 金丹 | 42 | ×0.14 | ×0.14 | 2 | — |
| 元婴 | 22 | ×0.14 | ×0.14 | 2 | — |

⚠ **灵根加成与「最后的机会」加成必须保留**（+15 分）：高阶检查曾被**整块覆盖**成旧值 ⇒ 实测金丹只有三成把握、元婴只有一成。
⚠ 灵根加成 `gradeBonus`：≥2 加 10、1 加 0、其余减 8。
⚠ 第四张卡 `breakthrough_<境>_3`「最后的冲关」：授业者亲自护法，多一份底气。

### 6.5 年速（年速是**呈现层**，不是规则）

公式在 `packages/adventure/progression.js::playbackSeconds`：

```
1 年 = clamp(5400 ÷ 境界基础寿元, 4, 120) 秒
```

三处例外：

| 例外 | 值 | 理由 |
| --- | --- | --- |
| 童年（0–6 岁） | 固定 8 秒/年 | |
| 95 岁及以后 | 封顶 3 秒/年 | |
| **凡身档（境界 0）** | **30 秒/年** | 境界 0 = 还没引气入道那一段；按 K÷寿元只有 4 秒/年，那几年几乎看不到旁白 |
| 长途行动（闭关 / 远行 / 渡劫准备） | 保持现状 | 那是「闭关跳过」的语义 |

⚠ **改动它不会改任何规则结果**：状态逐月推进、决策序列、事件表、结局一个字节都不变（`eventsfid` / `eventseq` 两道门禁守着）⇒ **不进任何门禁基线**。

### 7.2 一个域里存什么

固定三段形状 `[标题, 正文, 选项提示语数组]`：

- 正文为 `null` ⇒ 走本分片的 `dynamic`（按当时的情形现写一段话）。经典线 13 张有 `dynamic`，修仙线分片**一律没有**。
- **提示语条数必须与规则层选项数一致**，对不上当场报错（`Missing readable scene: <id>`）—— 这是「内容漏了」最早的信号。
- 分片文件**只放内容**；`makeReadable` 只做装配 —— 别把剧情写进这个文件。
- **降级不崩**：缺一行 ⇒ 退回规则层说法 + `console.warn`，不让一格漏字把整局白屏。

### 7.3 修仙线只接管三样

| 项 | 归谁 | 理由 |
| --- | --- | --- |
| 标题 | 表达域 | 说法 |
| 正文 | 表达域 | 说法 |
| 选项提示语 | 表达域 | 说法 |
| **选项字面（label）** | **规则层** | 它要跟选项 id 对齐 |
| **结算回话（reply）** | **规则层** | 它是后果的一部分 |

⚠ **只换说法，不换事实**：效果、判定、代价、月份、后续事件一个字都不动。

### 7.4 写作规范（六条）

1. **一句一件事**：正文只讲场景；规则条款归到提示语。
2. **正文 ≤ 90 字**（表达域门禁的判据，逐分支量）。
3. **专名不许改、不许删、不许发明**：
   - 不许丢：规则层有的专名表达域必须留着（门禁查 `docs/expression-vocabulary.json` + 22 个硬编码人名）。
   - 不许编：表达域出现的专名必须在词表或规则层原文里出现过。
4. **提示语三段式**：写玩家**已经知道**的条件、费用、危险。
5. **不展示后台概率**：判据正则 `/成功率|成功机会|这次安排|\d+%/u`，扫 352 张卡 × 每个选项 × 每条分支（规则层的 label、规则层的 hint、表达域的 hint 三处都查）。
   理由：内部成功率是给作者看的数；玩家看到「成功率 40%」就等于知道哪个选项是正确答案 ⇒ 选择就没意义了。
6. **像人说话，不像公文**：短句；不用「诸如 / 遂 / 乃 / 其」；保留修仙世界具体感。

### 7.5 四套专名表 + 两道后处理

| 表 | 位置 | 规模 | 作用 |
| --- | --- | --- | --- |
| 表达域专名总表 | `docs/expression-vocabulary.json` | 10 人 / 19 地 / 18 物 | 表达域不许发明内容；人工维护（中文无法可靠自动分词） |

| 别名替换表 | `packages/adventure/progression.js::EXTRA_NAMES` | 24 条 | 规则层别名 → 随机名，同时保留「长老 / 掌柜 / 执事 / 宗主」称谓 |

⇒ 表达域**必须原样保留**规则层专名，因为这两道工序要靠名字匹配。

### 7.6 表达域门禁的八条断言

`scripts/verify-event-expressions.mjs`（修仙线），实测全绿：

| 断言 | 实测 |
| --- | --- |
| 一条不漏（且没有多余） | 352 张都有说法，缺 0、多余 0 |
| 提示语数量对齐选项数 | 对不上 0 条 |
| 正文 ≤ 90 字（**每个分支**都量） | 超的 0 条 |
| 按情形说话的卡，说法种数与规则层一致 | 不一致 0 处 |
| 不许发明规则层没有的专名 | 发明 0 处 |
| 规则层有的专名表达域都留着 | 丢 0 处 |
| 选项与提示语都不泄露内部成功率 | 漏 0 条 |
| 表达域输出与基线逐值全等（352 条 × 3 状态） | 差异 0 处 |

⚠ **分支探针的教训**：早先只用 3 态探针，`network_mentor` 只量到「安全」那一支，**危险那一支 129 字门禁完全没看见**。
⇒ 现在用 12 份刻意不同的状态（身份 5 种 × 灵根 4 种 × 在世的人 3 种 × 境界 3 种 + 4 份专门拉开分支的状态）。

⚠ **判据改过两次**：

- 「说法种数」早先数规则层源码里的字符串字面量个数 ⇒ **能被绕过**（把句子拼进模板字符串，引号就没了；实测分片作者正是这么绕过去的）⇒ 改成看**行为**：在一组探针状态下分别跑原函数与新函数，数「能说出几种不同的话」。
- 「专名」早先把句尾 2–4 个汉字当人名 ⇒ **假阳性满屏** ⇒ 改成双向判据。

## 第 8 章：旁白层（正在过的日子）

> 归属：⑤表达域（文本）+ ④节奏域（排期）。

### 8.1 目标：追上官方「一件大事 + 六件小事」

官方对照报告 §6.2 的口径：

```
一生流水条数 ÷ 一生决策卡数
官方：中位 362 ÷ 56 = 6.46
```

我们同口径一度只有 **4.00**（一生流水中位 162 ÷ 决策卡中位 41）⇒ **骨架有了，肉不够**：玩家读到的全是「决定」，没有「正在过的日子」。

⇒ 新增「人生场景池」后：

| | 阶段 5 之前 | 阶段 5 之后 | 官方 |
| --- | --- | --- | --- |

### 8.2 两池五通道

| # | 通道 | 写什么 | 排期 | 挑行 | 占随机流？ |
| --- | --- | --- | --- | --- | --- |
| 1 | **日常 / 拾遗** `automaticStory` | 事后交代、路上捡到的东西、东西用旧 | `c.dailyAt`（24–48 个月；长线期间 18–36） | `c.dailyMemory` 记账，用过的行不再用 | **是**（`daily` 流） |
| 2 | **印记后果** `aftermathStory` | 做完决定之后，后果在旁白里陆续显现 | 同上，**独立通道** | `AFTERMATH` 表按顺序找第一条未写过的 | 否 |
| 3 | **人生场景** `sceneStory` | **当时正在发生** | **种子哈希**（12–60 个月，按人生阶段） | **顺序走池** | **一个都不占** |
| 4 | **凡人谋生** `mundaneDaily` | 做工、开铺、柴米油盐 | 与第 1 条同一拍 | 种子哈希 | 否 |
| 5 | **家族口信** `familyMessage` | 故乡消息 | 写进 `c.mail.body`，走讣告/家信通道 | `random('daily')` 选 4 选 1 | 是 |

| --- | --- | --- | --- | --- | --- |

### 8.3 ⚠ 最要紧的一处技术约束

**规则层的 `delay()` 从 `events` 随机流抽签，而 `events` 流同时决定「这一批候选卡里发哪一张」。**

⇒ **旁白节奏一改，抽签次数就变 ⇒ 整条决策序列跟着变**
⇒ 长线触达、内容覆盖、结局分布全要重审。

⇒ 所以**新通道一律用种子哈希**（`hashText`）：排期与挑行都不碰随机流。
实测：24 条固定人生的决策序列 **654 步逐条全等**（`eventseq` 门禁保持绿），而比值从 4.00 拉到 6.37 ⇒ **两者彻底解耦**：以后再调旁白密度，不必重审卡牌序列。

### 8.4 走池：顺序走，不记账

```
slot  = (本月 − 相位) ÷ 间隔          这一组的第几拍（只增不减）
index = (起始序号 + slot × 步长) 对行数取余
```

⚠ **步长必须与池长互素** —— 否则一条命里只能走到池子的 1/gcd 部分，那些行看着写了很多、其实一辈子轮不到（跨命并集看不出来 ⇒ 门禁要单独断言这条）。

⚠ **为什么不用「用过的行不再用」**：那要记账（`c.dailyMemory`），而存档校验要求每个键 ≤ 64 条 ⇒ 每组最多 64 行；可一条命能走到后期三百年，后期那组要走上百条 ⇒ **记账的做法必然写空**。

⚠ **降级规则**：赶路、探索、闭关、禁闭等情境**不发场景旁白**（让原有池讲）——「同一件事写两遍，比不写更糟」。

### 8.5 旁白的三道后处理

1. `prose()` —— 别名 → 随机真名。
2. `introduceText()` —— 首次出现的人物加「（角色）」。
3. `titleAllows()` —— 冷却闸，只压**自动旁白**；玩家的抉择记录（`kind:'choice'`）不算重复（「那是他自己的历史」—— 选过两次同一个选项就该记两次）。

## 第 9 章：数值层（判定与资源）

> 归属：②角色 + ③因果。

### 9.1 判定式（`engine.js::chance`）

```
score = base
      + 技艺值 × 技艺权重
      + 境界 × 境界权重
      + 属性值 × 属性权重
      + 道具加成
      + 旗标加成
      + 在世盟友加成
      − 体力不足惩罚（连续：体力越低扣得越多，最多 10）
      + 体魄 × 0.12
      + 时代加成
最终 clamp 到 [5, 95]
```

**三条设计意图**：

1. **「虚弱」是临时状态，不是永久减益**：体力低于 40 ⇒ 按差值连续扣分（最多 10 分），体力一恢复就还回去。
   以前是「体力低于 40 就固定扣 10 分」⇒ 一刀切 ⇒ 只要体力回不来就一直挂着 ⇒ **越输越没戏**。
2. **「体魄」是永久能力**（只增不减）：给的是稳定加成，不随体力起伏；而且**出力的事才长体魄**，静坐读书不长。
3. **判定上限 95**：再强的准备也有风险；下限 5：再差也留一线。

### 9.2 五轴能力

| 轴 | 含义 | 影响 |
| --- | --- | --- |
| 体力 `health` | **资源**（0–100） | 会被耗掉，靠调养与丹药回；低于 40 判定打折 |
| 心境 `mind` | 专注与情绪稳定 | 冲关失败会掉；家人离世会掉 |
| 悟性 `insight` | 理解与学习 | 提高修行积累速度；冲关的悟性权重项 |
| 胆识 `courage` | 面对风险 | 战斗、探险、掠夺类选项 |
| 仁心 `empathy` | 体察他人 | 交游、人脉、`aid()` 的盟友加成 |
| **体魄 `constitution`** | **能力**（0–100） | 判定加成（×0.12）、修行速率、寿元修正；**只增不减** |

⚠ **体魄不是属性**（不在 `player.stats` 里），它住在 `state.life.cultivation.v12.body.constitution`。
⇒ 五轴雷达图取的是「悟性 / 胆识 / 仁心 / 心境 / 体魄」，**体力不出雷达**。

### 9.3 重心与档位：重心有后果

生活重心有七种（`ACTIVITIES`）：读经、练剑、丹术、研阵、做工、交游、调养。

| 档位 | 累计月数（**每一项重心各自**算） | 修行积累 | 技艺成长 |
| --- | --- | --- | --- |
| 生疏 | 0–11 | ×1.00 | ×1.00 |
| 熟手 | 12–35 | ×1.10 | ×1.15 |
| 专精 | ≥36 | ×1.20 | ×1.30 |

⚠ **档位按「每一项重心各自的累计月数」算**（`c.activityMonths[id]`），不是连续月数 ⇒ **不新增存档字段**；代价是换来换去的人每一项都能攒到熟手/专精。

⚠ **「修行积累」那一列只管到筑基之前**（境界 ≤ 1）：筑基之后瓶颈换成**主药与完整心法**，再加修行会把金丹/元婴推得太早。
⚠ 早期版本（×1.25 全程）把金丹踏入年龄推到 87 岁、元婴 186 岁 ⇒ 打破窗口 ⇒ `cadence` 门禁报红。

⚠ **技艺加成会改变生死**：判定式是 `chance()`，技艺进判定 ⇒ 专精档把剑/阵法/丹术练得更稳 ⇒ **本该输掉的关口能活下来**（实测：一条原本 54 岁战死的命，活到 276 岁、结局 `loose_home`）。这是**有意的正反馈**，但改倍率前先想清楚会翻掉哪些判定。

### 9.4 寿元计划：唯一来源在规则层

`lifespanPlan12(s)` 返回 `{limit, age, left, next, nextRealm}`，**呈现层只读这个，不许自己算**。

⚠ 规则层算一次 → 写进 `state.life.cultivation.lifespanLimit` → 呈现层只读。
呈现层以前各读各的（小程序读境界基础寿元）⇒ 登记卡上写的寿元与实际能活的岁数对不上。

### 9.5 经济

- 每年 12 月结算一次（`annualCultivationSettlement`）：收入 − 家用 − 路费。
- **欠账从净结余逐年偿还**（`state.flags.debt`），不会把人生卡在无钱可走的门前。
- 家族汇款、包裹托送有**真实路径**：封航会拦住商队、包裹会因「原收物人已离世」而退回、暴露会打断当前行动。
- 灵石上限 100,000；其他属性 0–100。

**为什么有三把尺**：以前那把尺永远是绿的——豁免名单有 263 张（387 张里的 68%）⇒ 每条命 43 张卡只算了 6 张 ⇒ 实测「最挤 10 年 4 张」，上限 5 ⇒ 绿。而玩家真正常遇到的是**全卡**口径的「最挤 10 年 15 张」。

⚠ **分类由规则层给**（`gates.js::classifyCard`），指标**不许自己判前缀**（`t10reverse` ⑬ 那道反向验证就守着这条：把规则层的分类写坏 ⇒ 门禁必须变红）。

⚠ **上限是「规格」，不是「记录」**：改动内容让密度变大时，**必须**显式改 `HARD_LIMIT`（并重生成基线、写台账理由）。

### 10.2 棘轮机制

门禁判据是**「跟基线比」**不是「跟理想值比」。基线在 `tests/fixtures/metrics-baseline.json`，每次重生成都要写 `reason` 台账（现有 16 条变更记录）。

⚠ 未达标先钉在今天的值，缺口写在明面上（`spanMedian` 先钉 51，规格目标 15）。

### 10.3 触达审计：两种策略 + 分族

`scripts/audit-reach.mjs`，实跑 200 条命 × 2 种策略 = 400 条：

| 指标 | 实测 |
| --- | --- |
| 决策卡总数 | 352 |
| 两种策略都发过 | 238 |
| 真零触达 | **114** |
| 崩了 | **0** 条 |
| 16 条长线「有机会必发出」 | **全部 100%** |

**两种策略**（只用一种会量错）：

| 策略 | 住在哪 | 量什么 |
| --- | --- | --- |
| **固定偏好** | `scripts/lib/decide-policy.js` | 命与命之间**可比** |
| **随机探索** | `scripts/lib/rng.js::makeRng` | 能撞出偏好策略**永远不走**的分支 |

⚠ 「一次都没遇到」有两种原因：① **走不进去**（条件写错 / 队列被占 ⇒ 缺陷）② **这条偏好没选过**（不是缺陷）。只看一种偏好，量出来的「零触达」大半是假的。
⚠ 随机探索会让人生早死 ⇒ **随机策略不能单独当覆盖率口径**，只能当「找分支」的工具。

### 10.4 完备度审计：缺口必须双向登记

`scripts/audit-completeness.mjs` 盘点七项：事件表 / 人物 / 道具 / 境界 / 结局 / 年龄段覆盖 / 缺口清单。

**缺口双判**：

| 情形 | 判据 |
| --- | --- |
| 硬底线破了 | 直接报红 |
| 台账里有、现在还成立 | 绿（已知缺口） |
| 台账里有、现在**不**成立了 | **报红**（缺口被补上 ⇒ 该更新台账） |
| 现在成立了、台账里没有 | **报红**（新缺口，必须登记） |
| 台账里有脚本不认识的 | **报红**（台账过期） |

⇒ 「**缺口被补上也要报红**」是为了防**假门禁**：只在「新缺口」时报红 ⇒ 有人把判据放松、缺口静悄悄消失，门禁还是绿的。

### 14.2 改之前的检查清单

1. **这是不是「有意行为变更」？** 改规则层（`packages/` / `content/` 的判定逻辑）会改变整条决策序列 ⇒ 要走「变更前基线 → 差异审查 → 变更后基线」。
2. **这个数会不会在别处也写了一份？** 归山记最常见的病是「同一件事写了两份数字，其中一份必然发霉」。
   - 门槛在 `content/realm-thresholds.js`，不在 `cadence-table.js`。
   - 长线 id 在 `content/chain-ids.js`，不在 `gates.js`。
   - 寿元只有 `lifespan12` 一个来源，呈现层只读 `lifespanLimit`。
   - 「该不该发突破卡」只有 `breakthroughDue` 一份，调度器与指导卡都问它。
   - 豁免分类只有 `classifyCard` 一份，指标不许自己判前缀。
3. **改完要重算什么？**
   - 改了规则层 → 重算 `eventsfid` / `eventseq` 两道基线。
   - 改了内容密度 → 重生成 `tests/fixtures/metrics-baseline.json` 并**写台账理由**。
   - 改了触达 → 重写 `tests/fixtures/reach-gaps.json`（**与样本量绑定**）。
   - 改了表达域 → 跑 `scripts/verify-event-expressions.mjs`（会逐分支量字数）。
   - 改了旁白场景 → 检查每组 ≤ 64 行、步长与池长互素。
4. **改了被清单跟踪的文件 ⇒ 先重生成来源清单**：
   ```sh
   node scripts/gen-source-manifest.mjs --offline
   ```
   ⚠ 文档也在清单里 ⇒ **改文档也要跑**；顺序是「先改文件 → 重生成清单 → 再跑门禁」。

### 14.3 加一张新卡的完整流程

1. 在 `content/cultivation-stories.js`（或对应的内容表）写事件：`{id, title, text, choices, act}`。
2. 在 `content/expressions/events/<族>.js` 写说法：`[标题, 正文, [提示语…]]`，**提示语条数 = 选项数**。
3. 声明它在 `content/card-stages.js` 的阶段（如果它属于特定人生段）。
4. 判断它是不是豁免卡：结构性（人生节点）还是日常（玩家决定）？若是长线 ⇒ id 要进 `content/chain-ids.js`。
5. 想清楚它的**前置条件**（`requires`）、**判定**（`check`）、**后果**（`effects`）、**下一步**（`next`）。
6. 写一条**反向验证**：把某个关键值改坏，门禁必须报红。
7. 跑门禁：`node scripts/run-regression.mjs --group=fast`（规则层改动跑全量）。

### 14.4 写新卡时的写作规范（抄这一段就够）

- **正文 ≤ 90 字**，一句一件事。
- **选项写实际行动**，提示语只写玩家**已经知道的**条件、费用和必要危险。
- **不展示后台概率**，不讲存档 / 系统 / 旧规则，不提前确认成功或写未发生的伤病。
- **不在当前故事里的师承 / 能力选择直接隐藏**；存在但缺资源的机会可以显示禁用 + 一行原因。
- **每卡最多一个主要新人物 / 核心概念**；新人物第一次写职责并进入人物关系，后续保持同一身份。
- **不许发明专名**。
- 后续卡要读**真实状态**（家人是否在世、同伴是否还活着、商路是否通），不读抽象标记。
