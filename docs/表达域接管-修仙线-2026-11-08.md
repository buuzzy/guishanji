## 一、要解决什么

复盘实测（全仓 356 张卡）：

| 指标 | 修仙线（285 张） | 经典线（66 张） |
| --- | --- | --- |
| 说过人话的卡 | **0 张** | 66 张 |
| 正文中位字数 | 66 字 | — |
| 正文最长 | 130 字 | — |
| hint 中位字数 | 20 字 | — |

**问题不在长度，在密度**：一句里同时塞「是什么 + 会怎样 + 但有个限制」。

例（`content/story-rules10.js:22` 的 hint）：
> 顾魇能教测灵石不收的禁术，但要先见堂规；现在还没有拜师。

24 字，三个信息点挤在一句。

**改法**（复盘 §10 建议）：
1. **正文按「一句一件事」重写** —— 一句话只讲一件事。
2. **规则条款从正文挪到 hint** —— 正文只讲场景，条款归选项。
3. **hint 三段式**：`做什么` + `代价/风险/收益一句白话` + `不可选时差什么`。

## 二、架构：表达域怎么接管（已定）

### 2.1 接管点

`packages/adventure/engine.js` 的 `eventNode()` 里，**当前版本（规则十二）** 走新表：

```js
const READABLE_EVENTS = makeReadableEvents(CULTIVATION_EVENTS);   // ← 表达域
// rulesVersion===11/10/…/5 各走自己的快照表（一个字都不动）
```

### 2.2 只换三样

| 换 | 不换 |
| --- | --- |
| 标题（title） | 选项的字面（label） |
| 正文（text） | 结算后的回话（reply） |
| 选项提示语（hint） | 效果、判定、代价、月份、后续事件 |

理由：label/reply 多半是动作本身（「先回信核对旧事」），改写收益小、**改坏的风险大**（改错 label 会让 `progressionChoice` 的分支对不上）。

### 2.3 目录与形状

```
content/expressions/events/
  index.js      汇总 + makeReadableEvents()
  entry.js      20 张  山门 / 测灵根 / 魔道 / 妖兽 / 俗世前段
  trial.js      29 张  选拔 / 突破 / 宗门评议
  sect.js       23 张  宗门修缮 / 试炼 / 归山 / 世仇 / 家族
  wild.js       41 张  散修 / 魔道 / 妖兽
  child.js      37 张  童年 / 人脉网络
  material.js   36 张  突破材料
  twelve.js     32 张  规则十二专属（r12_*、thin_root_*）
  echo.js       17 张  回响（旧识 / 铜匣 / 恩师）
  mundane.js    50 张  俗世生活线（m11_*）
```

一条卡一行：

```js
export const rows = {
  reception: [
    '山门外的队伍',                       // 标题
    s => '队伍排到第七个人时，有人回头看了你一眼。',   // 正文（可以是函数）
    ['测灵石会记下你的根骨。', '山下有人在招学徒。', '家里还等着你的消息。'],  // 每选项一条
  ],
};
```

⚠ **提示语数量必须和规则层的选项一样多** —— 对不上直接报错（内容漏了的最早信号）。

### 2.4 函数正文：表达域自己算分支

**126 张卡的原正文是函数**（按当时情形说不同的话）。表达域必须能自己算出分支。

**约束（实测得出）**：这些函数用到 40+ 个辅助符号，分三类：

| 类别 | 例子 | 表达域能不能用 |
| --- | --- | --- |
| 纯状态读取 | `c(s)`=`s.life.cultivation`、`r(s)`=`c(s).story10`、`p(s)`=`c(s).progression`、`m(s)`=`c(s).mundane` | ✅ 自己写 |
| 内容表查询 | `ROOTS`、`GEOGRAPHY`（`content/cultivation-world.js`） | ✅ import 数据层 |
| **规则层判定** | `rules12`、`sectProfile`、`stage12`、`homeReceiver12`、`rootLabel`、`canCultivate` | ⚠ 见下 |

**规则层判定怎么办**：

- `rules12(s)` = `c(s).v12` —— **就是一个状态字段**，表达域自己写 `s.life.cultivation.v12` 即可，零依赖。
- `sectProfile(s)` = 在 `content/rules12-world.js` 的 `SECT_PROFILES` 里按 `v12.sect` 找 —— 数据层，✅ import。
- `stage12(s)` = `QIGONG_STAGE_NAMES[qigongStage(c(s).progress)]` —— 全在 `content/cadence-table.js`，✅ import。
- `homeReceiver12(s)` = 在 `s.life.family.members` 里找在世的 —— 纯状态，✅ 自己写。
- `rootLabel(s)` = 「无灵根」或 `s.player.root` —— 纯状态，✅ 自己写。
- `canCultivate(s)` = `ROOTS[s.player.root].grade>=0 || r(s)?.body==='nativeBeast'` —— `ROOTS` 是数据层，✅ 自己写。

⇒ **结论：126 张函数正文全部可以在表达域内自足实现，不反向依赖规则层。**

⚠ **层方向是硬约束**：`content/`（数据层）不许 import `packages/adventure/`（规则层）。
已有 7 条许可证就是历史越界，**新代码不许再增加**（章程 §三）。

⇒ 表达域分片里**只能** import `content/` 下的模块。

### 2.5 降级而不是崩

缺一行 ⇒ 退回规则层自己的说法 + `console.warn`。
真正把住这件事的是门禁 `scripts/verify-expressions.mjs`（一条不漏 + 提示语数对齐）。

## 三、写作规范（分片作者照这个写）

### 3.1 正文

- **一句一件事**。一句话只讲一件事。
- **≤ 90 字**（当前最长 130 字）。
- **不塞规则条款**。「代价是多少」「多久」这类挪到 hint。
- **保留专名**（人名地名物件），因为：
  - `prose()` 靠名字做替换（把「嵇萝」换成玩家自己的名字）；
  - `introduceText()` 靠别名加身份注解（「（幽灯堂药库师兄）」）。
  ⇒ **专名不许改、不许删、不许发明新的**。

### 3.2 hint（三段式）

```
做什么 + 代价/风险/收益一句白话 + 不可选时差什么
```

- 不可选时差什么：引擎已经算好 `reasons`（`packages/adventure/engine.js` 的 `enabled`/`reasons`），界面会显示。
  ⇒ hint 写「做什么 + 后果」，**「不可选」那句不用写进 hint**（界面另有显示）。

### 3.3 语气

- 像人说话，不像公文。
- 短句。逗号断句，一句一个意思。
- 不用「诸如」「遂」「乃」「其」这类文词。
- 保留修仙世界的具体感（灵石、丹药、测灵石、闭关），别改成现代口语。

## 四、门禁（`scripts/verify-event-expressions.mjs`）

修仙线部分，六条：

| # | 判据 | 报红条件 |
| --- | --- | --- |
| ① | **一条不漏** | 285 张卡里任何一张没进表达域 |
| ② | **提示语数对齐** | 提示语条数 ≠ 规则层选项数 |
| ③ | **正文 ≤ 90 字** | 任一分支超过 90 字 |
| ④ | **说法种数一致** | 表达域能说出的说法种数 ≠ 规则层原函数能说出的种数 |
| ⑤ | **专名双向** | 表达域出现规则层没有的专名（发明）／规则层有而表达域丢掉了（漏） |
| ⑥ | **逐值全等** | 表达域输出与基线 `tests/fixtures/event-expressions.json` 不一致 |

⚠ **④「说法种数一致」怎么判**（**2026-11-08 改过一次**）：
早先数的是「规则层原函数源码里的字符串字面量个数」⇒ **能被绕过** ——
把句子拼进模板字符串（反引号）引号就没了，分支数对不上却查不出来（实测分片作者正是这么绕过去的）。
⇒ 改成**看行为**：在一组刻意不同的探针状态下分别跑规则层与表达域的函数，
数「**能说出几种不同的话**」。⇒ 模板字符串藏不住分支（分支还在，就还能说出不同的话）。

⚠ **⑤「专名双向」怎么判**：
- 正向（不许发明）：表达域文本里出现的专名，必须在词表里，**或者**在规则层**全部卡**的原文里出现过。
- 反向（不许丢）：规则层同卡原文里出现的专名（`PEOPLE_TERMS` 人工维护的人名表 + 物件名表），必须在表达域文本里出现。
- **地名放行**：大陆名是**动态值**（规则层 `homeName(s)` 取玩家的出生大陆）⇒
  照抄「青岚大陆」反而会对别的出生地说错，写成「老家」才是对的。

### 4.1 反向验证（十道，都必须报红）

| # | 注入的坏值 | 必须报红 |
| --- | --- | --- |
| ① | 改一个字 | ⑥ 逐值全等 |
| ② | 漏一条卡 | ① 一条不漏 |
| ③ | hint 数量对不上 | ② 提示语数对齐 |
| ④ | 正文超 90 字 | ③ 字数上限 |
| ⑤ | 说法种数对不上 | ④ 分支一致 |
| ⑥ | 专名被发明 | ⑤ 不许编 |
| ⑦ | 专名被丢掉 | ⑤ 不许丢 |
| ⑧ | 正文里的数量被改（三年→五年） | 差异审查「正文里的数量一个都没变」 |
| ⑨ | 提示语里编出数字（六个月→八个月） | 差异审查「提示语里的数规则层本来就知道」 |
| ⑩ | 专名被丢掉（差异审查那道） | 差异审查「变更前的专名都还在」 |

脚本：`scripts/t7-reverse.mjs`（默认在临时副本上做，工作区一个字节都不动）。

## 四点五、判据踩过的七个坑（2026-11-08 实测）

这一节的每一条都是**门禁自己先报红**才发现的 —— 记下来，后人别再踩。

### 坑 ① · 专名判据会「把句尾词组当人名」

**症状**：正常改写被判成「发明了专名」。「守魂口诀」「锁在堂中」这种句尾词组全被当成专名。

**根因**：中文没法可靠地自动分词 —— 句尾的词组与专名长得一模一样。

**修法**：改成两个可靠的方向：
- **不许丢**：词表（`docs/expression-vocabulary.json`）里的词 + 人工维护的人名清单（`PEOPLE_TERMS`），
  规则层同卡原文里有的，表达域必须原样保留。
- **不许编**：表达域里出现的专名，必须词表里有，**或者**规则层全部卡的原文里出现过
  （收集范围要含 title / text / hint / **reply / label** ——
  早先只收前三样 ⇒「顾长老」明明在回话里出现过却被判成「发明专名」）。

### 坑 ② · 「数引号个数」这条判据能被绕过

**症状**：分片作者把句子拼进模板字符串（`` ` ``），引号就没了 ⇒ 分支数对不上却查不出来。

**根因**：数的是**源码形态**，不是**行为**。

**修法**：改成**行为判据** —— 在一组探针状态下分别跑规则层原函数与表达域新函数，
数「能说出几种不同的话」（不同取值的个数）。
⇒ 模板字符串藏不住分支：分支还在，就还能说出不同的话。

### 坑 ③ · 探针状态不全 ⇒ 把正确的表达域误判成「多说了」

**症状**：`root_result` 报「0 种 → 6 种」—— 规则层那边算出 0 种。

**根因**：探针状态缺 `ROOTS`（灵根表，key 是**中文名**如 `'松骨灵根'`，不是 gold/wood）、
缺 `SECT_PROFILES`、缺 `mail` / `exam` / `wanted` / `chains` / `network.offer` 等字段
⇒ 规则层函数在探针下抛错 ⇒ 一条分支都测不出来。

**修法**：探针状态补齐，并**把探针写成「真实取值」**（灵根用中文名、宗门用真实 id）。
⚠ 这也说明：**分片作者自己写分支条件时同样要用真实灵根名** ——
写成 `['gold','wood',...].includes(s.player.root)` 永远为假，分支会永远走错支。

### 坑 ④ · 顶层 `const` 的 TDZ（同一个错踩了三次）

`STOPWORDS`、`BRANCH_PROBES` 都因为「声明在后面、使用在前面」而抛
`ReferenceError: Cannot access 'X' before initialization` ——
**门禁自己崩了**，任何分片都跑不完。

**修法**：跨函数用到的顶层变量，一律用 `var`（函数级提升，没有 TDZ）或者改成函数 + 惰性初始化。


### 坑 ⑤ · 探针里缺「俗世生活」那段数据 ⇒ 规则层读到就崩

**症状**：`m11_work_0` / `m11_family_0` / `m11_corpse_1~3` 报「能说出的说法 0 种 → 1 种」。

**根因**：修仙线末尾那段「不再做修士的日子」有二十来张卡的正文是**按状态说话**的
（谁跟你一起交货、死者是不是被害弟子、家人还在不在、有没有留下旧债）。
它们读的是 `s.life.cultivation.mundane`（规则层 `mundane(s)` 取的就是它）。
探针里那个字段只有个空壳（`people: []`、`corpse` 都没有）⇒
规则层那边 `person(s,'worker').role` / `m(s).corpse.taken` 直接抛错 ⇒ 算出「0 种说法」。

**修法**：探针里放一份**真的像那么回事**的俗世状态（见门禁里的 `mundaneVariants()`），
四份切片刻意把每个分支点都拉开：worker 的名字与身份、corpse 的三个标记、
spouse/child 在不在、旧事标记（notes）、做什么活（job）。
⚠ **分片作者自己写分支条件时同样要用真实字段名** ——
`s.life.cultivation.mundane.people` 写成 `s.people` 就永远取不到。

### 坑 ⑥ · 「一」不是数量、量词可以换字、提示语里的数是从规则层搬来的

**症状**：差异审查报「正文里的数字变了 21 张」「专名丢了 2 张」，但逐条看下来**事实一个都没变**。

**根因**：三个不同的误判混在一起。

1. **「一」被当成了数量**：「一种活法」「一条路」「一块木牌」在中文里是**不定量**说法，
   不是事实数字 ⇒ 改写只是把「还需要三年」说成「还得练三年」就被判「多了个数」。
2. **量词换了字**：「门后两名杂役」→「门后两个杂役」是人数没变、量词换了。
   按字面比 ⇒ 误报；**按数值比**（两名 = 两个 = 2）⇒ 不报。
3. **提示语里新出现的数是照抄事实**：写作规范要求把「要多久」「代价多少」挪到提示语里，
   所以「回话要等六个月」（= 选项的 `months: 6`）、「你得真的有两枚灵石」（= 选项的 `cost: {stones: 2}`）
   都是**规则层本来就有的事实**，不是编出来的。

**修法**（共用工具 `scripts/lib/text-numbers.mjs`，门禁与差异审查同一套算法）：
- 「一」不算数量（`numberValues` 把它丢掉）；
- 比数值不比字面（中文数字先解析成整数再比）；
- **正文**里的数量必须前后**完全一致**（不许丢、不许改、不许多出）；
- **提示语**里出现的数必须能在规则层那张卡的事实数字里找到
  （事实 = 卡面文字里的数 + 选项的 `months` / `cost` / `requires` / `check` / 效果里的数）。

⚠ **这条也反过来教育了改写的人**：表达域在正文里**不许加规则层没有的数**
（实测有一张卡把规则层的「是不同的账」写成了「是三笔不同的账」⇒ 已改回）。

### 坑 ⑦ · 大陆名是动态值，「不许丢专名」会把正确的改写判成错

**症状**：差异审查报「`echo_friend` 丢了青岚大陆」。

**根因**：规则层用 `homeName(s)` 取「玩家的出生大陆」—— 探针里出生地是青岚大陆，
所以变更前的正文里会出现「青岚大陆」。表达域把它写成「老家」才是**对的**
（换个出生地也对）；照抄「青岚大陆」反而会对别的出生地说错。

**修法**：**大陆名不参与「不许丢」检查**（与门禁「地名放行」同口径）。
⚠ 但**人名、物件名照旧不许丢** —— 「阿宁」这类必须原样保留。

## 五、基线纪律

修仙线有**两份**基线，都由 `scripts/verify-event-expressions.mjs` 生成（同一批探针状态！）：

| 文件 | 是什么 | 怎么生成 |
| --- | --- | --- |
| `tests/fixtures/event-expressions-pre-rewrite.json` | **变更前**：规则层原文 | `node scripts/verify-event-expressions.mjs --write-before` |
| `tests/fixtures/event-expressions.json` | **变更后**：表达域接管后的输出 | `node scripts/verify-event-expressions.mjs --write` |

- 生成时用**三个状态变体**（沿用经典线的 `VARIANTS` 三态），
  因为函数正文按当时情形说话 —— 只测一种状态等于没测。
- ⚠ **两份基线必须用同一批探针** ⇒ 所以都由门禁脚本生成，探针只此一份。
  否则差异审查会把「探针变了」误当成「文案变了」⇒ 差异审查就废了。
- 基线**重生成**必须在 T7 全部写完后一次性做，理由写进 `docs/refactor-divergence.json`。
- 门禁必须能**反向验证**：注入坏值后基线不匹配 ⇒ 退出码 1。
- 差异审查用 `scripts/t7-diff.mjs --before=tests/fixtures/event-expressions-pre-rewrite.json`，
  审五件事：一张卡不许少、选项数不许变、正文里的数量不许变、
  提示语里的数规则层本来就知道、专名不许丢。

## 六、风险与兜底

| 风险 | 兜底 |
| --- | --- |
| 表达域写错导致某条卡说错话 | 门禁④分支数 + ⑤专名双向 + ⑥逐值全等，三层拦 |
| 漏写一张卡 | 门禁① + 引擎降级（退回规则层说法，不白屏） |
| 改坏旧版本（5–11） | 接管点只在 `rulesVersion===12`；旧版走各自快照表 |
| 规则层与表达域说法打架 | 表达域只换三样，**事实一个都不动** ⇒ 数值/期限/代价天然一致 |
